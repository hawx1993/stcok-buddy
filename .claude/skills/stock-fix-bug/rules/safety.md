# 防回归规则

目标：修复根因，同时保护真实数据链路、类型安全、React 状态一致性和性能边界。

## 根因优先

禁止用以下方式制造“看起来修好了”：

- 空 catch 后返回 `[]`、`null`、`{}`。
- 删除业务逻辑、删除校验、删除 Hook 或 effect 依赖。
- 注释掉功能、测试或错误分支。
- 新增 fallback/mock/fake/demo/sample/preview 行情数据。
- 降低 tsconfig、关闭 lint、跳过测试。
- 用 `any`、`as any`、`as unknown as`、`@ts-ignore` 掩盖类型问题。

必须让错误路径可见：错误态、空态、loading、日志或上抛到调用方处理。

## 真实数据安全

股票、行情、板块、新闻、K 线、分时图相关修复必须检查：

- 是否仍走统一 provider 层。
- stock-sdk 支持的能力是否优先使用 stock-sdk。
- stock-sdk 和备用真实数据源都不可用时，是否展示明确空态/错误态。
- 是否没有合成 K 线、合成分时、硬编码价格、假新闻、假板块排行。
- React 组件是否没有直接请求第三方行情接口。

## TypeScript 安全

- 类型要表达业务含义，不要只追求编译通过。
- 优先复用现有共享类型。
- 修改 public API 类型必须说明影响范围。
- 异步失败路径必须有类型化处理。
- 不新增全局类型污染或循环引用。

## React 安全

修复 React bug 时必须检查：

- Hook 是否仍在顶层调用。
- effect 依赖是否完整，未通过删除依赖规避问题。
- 闭包是否读取旧状态。
- 状态同步是否存在竞态或重复请求。
- 列表 key 是否稳定。
- render 中是否引入昂贵计算或副作用。
- 大组件是否没有继续膨胀；必要拆分只限直接相关区域。

## SQLite / 实时行情安全

- 不在每条行情消息到达时立即写库。
- 优先 memory cache、batch flush、transaction、queue。
- 不阻塞 Electron 主进程或 renderer。
- 批处理失败要暴露错误，不能静默丢数据。

## 性能与兼容

修复前后检查：

- 是否增加不必要的全量遍历、同步 IO、重复网络请求。
- 是否改变缓存键、持久化格式、IPC payload 或 public API。
- 是否影响旧数据迁移或缺字段兼容。
- 是否引入新的渲染循环或无限 effect。

## 回归检查清单

提交前逐项确认：

- 根因已解释，不是只修表象。
- 原 bug 路径有测试或替代验证。
- 错误路径不会静默吞掉。
- 用户未要求的功能没有被修改。
- 真实数据链路没有被 mock/fallback 替代。
- typecheck/lint/build 没有被绕过。
- `git diff` 每一处改动都与 bug 直接相关。
